## 1. 何をやっているか（30秒版）

西村さんが数字を打つ（例「40,140」）→ Chrome の X で @monja_no_KENT としてフォロー中タブ40件・おすすめタブ140件にいいねする → フォロワー数と当日投稿の被いいねを読む → `log.py` で記録 → GitHub Pages のダッシュボードを更新 → 結果を報告する。

目的はフォロワーを増やすこと。いいね自体が目的ではなく、**いいねで露出を取って自分の投稿を見てもらい、被いいね→フォローにつなげる**のが狙いです。

## 5. 分析で分かっていること

このデータを元に西村さんに提示済みで、納得されています。

### 5-1. フォロワーが増える仕組み
- フォロワー増 と 被いいね（自分の投稿がもらういいね）の相関：**r = +0.80**
- フォロワー増 と 送ったいいね数の相関：**r = +0.27**
- つまり「いいねをたくさん送る」より「自分の投稿が見られる」ほうが効く。いいねは露出を取るための手段。

## 6. 環境の注意点

### 6-1. Chrome とアカウント
- 西村さんの実 Chrome を使う。@monja_no_KENT と @Umapro_ryo の両方にログイン済み。
- **松村さんの運用セッションが同じ Chrome を共有している。** そちらが動くとアカウントが @Umapro_ryo に切り替わり、こちらのループが消える。9/9〜9/12 の間に10回以上起きた。対処は指示書6-②。
- 西村さんには「西村と松村は時間をずらして回してください」と伝えてあるが、守られないことが多い。**毎回、開始前と各タブ切り替え時にアカウントを確認する**のが唯一の防御。

### 6-2. macOS 権限
- **システム設定 → オートメーション → Google Chrome は許可済み。** AppleScript で Chrome を最前面にできる。
- **アクセシビリティは未許可。** System Events でのウィンドウ操作・キー送信はできない。
- TCC（権限）の書き換えは Codex からもできない。ユーザー操作が必要。

### 6-3. Chrome の状態
- ウィンドウが7〜10個開いていることが多く、x.com/home が複数ある。AppleScript の `set index of w to 1` が効かないことがある。`document.title` に目印を付けて特定する（指示書6-⑥）。
- Preview や Claude デスクトップが最前面にいるとタブが `hidden` のまま。ユーザーにクリックを依頼する。

### 6-4. X の DOM
- タブ名は UI 言語で変わる：`For you`/`おすすめ`、`Following`/`フォロー中`。両方試す。
- 投稿は `article`、いいねボタンは `button[data-testid="like"]`（済みは `"unlike"`）、リポスト表示は `[data-testid="socialContext"]`、返信は「返信先」/「Replying to」テキストか、スレッド接続線（幅2pxの縦線）で判定。
- タイムラインは絶対配置で DOM 順≠表示順。座標で判定している箇所がある（ランナーの `isReply`）。
- 警告テキスト：`might be automated` / `Try liking` / `Rate limit` のいずれか。
